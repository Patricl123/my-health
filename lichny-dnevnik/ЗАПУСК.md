# Дневник «Тихо»: SQLite без Firebase

Firebase больше не используется. Вход, проверка доступа, сохранение и резервные копии обслуживаются вашим сервером. SQLite-файл создаётся автоматически. В ежедневном использовании достаточно открыть сайт с телефона, войти и писать.

Подготовлен архив **`tiho-site.zip`** с собранным сайтом и сервером. На хостинге не требуется устанавливать npm, Python-библиотеки, создавать таблицы или писать SQL. Первичное размещение в вашем аккаунте нужно выполнить один раз. Интернет-ссылка ещё не создана — доступа к вашему аккаунту хостинга в этой сессии нет.

## Бесплатный хостинг: проверка условий

Проверено 9 ноября 2026 года по официальным источникам. Основной вариант — **alwaysdata Free / Public Cloud**, для личного некоммерческого дневника:

- [alwaysdata](https://www.alwaysdata.com/en/) прямо указывает регистрацию без банковской карты и отсутствие срока окончания бесплатного тарифа.
- [Тариф Free](https://help.alwaysdata.com/en/docs/admin-billing/billing/public-cloud-prices/): 1 ГБ для файлов, почты и баз суммарно, 256 МБ RAM, 1/4 CPU, резервные копии хостинга за 3 последних дня. Бесплатный сайт размещается на адресе аккаунта `ИМЯ.alwaysdata.net`. Фоновые сервисы на Free запрещены; здесь используется обычный Python WSGI-сайт.
- [Архитектура хранения](https://help.alwaysdata.com/en/docs/technical-specifications/architecture/): HTTP-серверы работают с локальным постоянным диском XFS. Это подходящий способ размещения SQLite-файла на сервере. SSH использует удалённый доступ к тому же хранилищу: не открывайте и не копируйте живой SQLite-файл вручную из SSH во время работы сайта; скачивайте JSON через сам дневник.
- [Python](https://help.alwaysdata.com/en/docs/web-hosting/languages/python/) и [Python WSGI-сайты](https://help.alwaysdata.com/en/docs/web-hosting/sites/add-a-site/) поддерживаются хостингом. Для проекта нужен Python 3.11+; выбирайте 3.13 или 3.14, если доступны.

Платные услуги, карту, автоматическую оплату, покупку домена и переход на Plus подключать не нужно. Выбирайте именно **Free**, а не платный пробный тариф. Если при регистрации Free требует карту или оплату, остановитесь: актуальный сценарий регистрации нужно перепроверить до подключения услуг. Превышать доступное место нельзя; при заполнении диска сервер сообщает ошибку и не показывает «Сохранено».

## 1. Создайте бесплатный аккаунт

1. Откройте [alwaysdata](https://www.alwaysdata.com/en/) → **Free / Register**. Создайте аккаунт, подтвердите почту и выберите **Free**, стоимость **0 €**. Банковские реквизиты не добавляйте.
2. Запомните имя **аккаунта хостинга**. Например, если выбрали `myquietday`, сайт будет на `https://myquietday.alwaysdata.net`.
3. В панели откройте **Remote access → SSH**. Включите доступ и задайте пароль SSH, если он ещё не создан. Логин и адрес сервера указаны в панели. [Официальная инструкция SSH](https://help.alwaysdata.com/en/docs/web-hosting/remote-access/ssh/).

Дальше в командах заменяйте `ACCOUNT` на своё имя аккаунта. Если имя SSH-пользователя отличается от имени аккаунта, используйте логин, показанный панелью.

## 2. Загрузите готовый архив и подготовьте сервер

На этом компьютере в PowerShell:

```powershell
cd "C:\Users\imash\Desktop\my health\lichny-dnevnik"
scp .\tiho-site.zip ACCOUNT@ssh-ACCOUNT.alwaysdata.net:tiho-site.zip
ssh ACCOUNT@ssh-ACCOUNT.alwaysdata.net
```

Команды попросят пароль SSH. Он вводится в терминале скрыто — передавать его в чат не нужно. Если `scp` недоступен, можно загрузить архив по [SFTP](https://help.alwaysdata.com/en/docs/web-hosting/remote-access/sftp/) в домашнюю папку аккаунта, затем открыть SSH.

В открывшейся SSH-консоли хостинга выполните:

```bash
python3 -m zipfile -e ~/tiho-site.zip ~/tiho-site
cd ~/tiho-site
python3 -m server.manage init --origin https://ACCOUNT.alwaysdata.net
```

База и конфигурация создадутся сами в **`/home/ACCOUNT/tiho-data/`**, отдельно от папки сайта **`/home/ACCOUNT/tiho-site/`**. Команда напечатает **одноразовый код настройки**. Оставьте его у себя: он нужен при первом открытии сайта, чтобы посторонний не занял личный вход.

Эта команда не создаёт облачную базу, не обращается к платным API и ничего не оплачивает. При повторном запуске `init` откажется изменять уже существующие данные. Если Python по умолчанию старее 3.11, выберите 3.13/3.14 в панели и используйте соответствующую команду `python3.13`/`python3.14`.

## 3. Включите сайт

В панели alwaysdata откройте **Web → Sites**. Если сайт `ACCOUNT.alwaysdata.net` уже создан, откройте его настройки; иначе нажмите **Add a site**.

Укажите:

- **Address**: `ACCOUNT.alwaysdata.net`.
- **Type**: **Python WSGI**.
- **Python version**: **3.13** или **3.14**.
- **Application file**: `/home/ACCOUNT/tiho-site/wsgi.py`.
- **Working directory**, если поле есть: `/home/ACCOUNT/tiho-site`.
- **Processes/workers**, если поле есть: **1**. Дневник рассчитан на одного владельца; несколько устройств поддерживаются.
- **SSL → Force HTTPS**: включить. [Официальная инструкция](https://help.alwaysdata.com/en/docs/web-hosting/sites/ssl-tls/redirect-http-to-https/).
- **HTTP cache**: оставить выключенным. Приложение само кэширует только оболочку, а запросы к личным данным всегда идут на сервер.

Не выбирайте Static files для всего сайта: это приложение с сервером, а не только HTML. Отдельную базу данных в панели создавать не нужно. Сохраните настройки и перезапустите сайт кнопкой Restart.

## 4. Один раз создайте личный вход

Откройте **`https://ACCOUNT.alwaysdata.net`** на телефоне:

1. Вставьте одноразовый код настройки из шага 2.
2. Укажите свою почту и придумайте пароль от 12 символов. Это пароль дневника, он может отличаться от пароля хостинга. Письмо для подтверждения не требуется.
3. Нажмите **«Создать личный вход»**.

После этого открытая регистрация закрывается навсегда для этой базы. Дальше на любом устройстве достаточно почты и пароля. Настройка базы и SQL-команды больше не нужны. Сессия хранится до 30 дней; кнопка выхода отзывает её на сервере.

## Резервная копия и восстановление

В **Настройках дневника**:

- **«Скачать все записи»** — выгружает все сохранённые записи в JSON, без пароля и сессий.
- **«Восстановить из копии»** — выберите JSON-файл. Сервер проверит все записи и покажет количество дней.
- **«Дополнить»** — добавляет отсутствующие даты, существующие дни остаются как есть.
- **«Заменить всю историю»** — восстанавливает точное содержимое копии, включая удаление дней, которых в ней нет. Требуется подтверждение.

Проверка и восстановление выполняются только после входа. Повреждённый файл ничего не меняет. Изменения в базе применяются одной транзакцией. Перед восстановлением сервер хранит страховочную копию текущей истории внутри SQLite; остаются 3 последние такие копии. Пароль, аккаунт и сессии из JSON не восстанавливаются и остаются прежними.

Поддерживаются JSON-копии этой версии (`formatVersion: 2`) и прежней Firebase-версии (`formatVersion: 1`). Из старой копии автоматически восстанавливаются сохранённые записи; вложенные `deviceDrafts` остаются в JSON, о чём сайт предупреждает.

Текущие черновики остаются в браузере и не заменяются восстановлением. Новые резервные копии содержат только записи, подтверждённые сервером. Чтобы включить черновик в такую копию, сначала отправьте его. При конфликте можно отдельно скачать черновик через дневник.

Файл JSON содержит записи открытым текстом — храните его у себя. Резервная копия провайдера не заменяет личную копию. Для выгрузки последней страховочной копии через SSH, если восстановили не тот файл:

```bash
cd ~/tiho-site
python3 -m server.manage export-recovery > ~/tiho-before-restore.json
```

Скачайте этот JSON через SFTP и восстановите его через сайт. Не редактируйте SQLite вручную.

## Перезапуск и обновление сайта

Перезапуск веб-приложения не удаляет базу или личный вход. При обновлении заменяются только файлы в `~/tiho-site`, а **`~/tiho-data` остаётся на месте**. Архив сайта никогда не содержит базу, пароль, cookie или серверный `config.json`.

Перед обновлением скачайте JSON через дневник. Загрузите новый `tiho-site.zip`, распакуйте его в ту же папку сайта и нажмите Restart в панели. **Не запускайте `init` повторно, не удаляйте `~/tiho-data`, не заменяйте базу пустым файлом и не храните её в `/tmp`.** Если файл данных недоступен, сервер откажется запускаться — пустая замена автоматически не создаётся.

## Если забыли пароль

Войдите в свой аккаунт хостинга, откройте SSH и выполните:

```bash
cd ~/tiho-site
python3 -m server.manage reset-password
```

Дважды введите новый пароль скрытым вводом. Записи сохранятся, старые сессии будут отозваны. Платный почтовый сервис для сброса не нужен.

## Локальный запуск на этом компьютере

Python 3.14 и Chrome уже обнаружены. Сборка сайта находится в `dist`.

```powershell
cd "C:\Users\imash\Desktop\my health\lichny-dnevnik"
npm.cmd run setup
npm.cmd start
```

Откройте **`http://127.0.0.1:8000`** на этом компьютере и создайте вход с кодом, напечатанным `setup`. Локальные данные будут в отдельной игнорируемой папке `server-data`. `setup` выполняется только один раз. Это локальный адрес, а не интернет-ссылка для телефона.

Для изменения исходников и повторной сборки:

```powershell
npm.cmd install
npm.cmd run build
npm.cmd run package
npm.cmd test
```

`npm.cmd run package` создаёт новый `tiho-site.zip`. Для запуска сервера на другом компьютере нужен Python 3.11+; путь при необходимости можно указать переменной `PYTHON_EXE`. `npm.cmd run dev` предназначен для разработки с API на порту 8000; адрес origin в конфигурации сервера при таком режиме должен совпадать с адресом Vite.

Тесты используют собственную временную SQLite в `.test-runtime`, не облачную и не вашу личную базу. Результаты описаны в [ПРОВЕРКА.md](ПРОВЕРКА.md).

## Защита данных

Владелец один. Все API записей, копий и восстановления проверяют сессию на сервере. Пароль хранится как соль и PBKDF2-SHA256 с 600 000 итераций. Случайная cookie сессии имеет HttpOnly, SameSite=Strict и Secure на HTTPS; в базе хранится только её хеш. Изменяющие запросы проверяют origin и CSRF-токен. Вход ограничен по числу попыток. База и конфигурация лежат вне публикуемых файлов.

Черновики находятся в этом браузере, переживают перезагрузку и остаются после выхода. На общем устройстве их можно очистить в настройках. Это не сквозное шифрование от администратора хостинга: провайдер обслуживает сервер и хранит файлы. Приложение не использует ИИ, аналитику и медицинские рекомендации.
