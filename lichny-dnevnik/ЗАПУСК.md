# Запуск «Тихо»

Дневник реализован в этой папке. Для личной интернет-ссылки нужно создать проект в вашем Google/Firebase-аккаунте и войти в него при публикации. Пароль от Google или от дневника передавать в чат не нужно.

## Бесплатное размещение

Условия проверены 9 ноября 2026 года по официальным страницам:

- [Firebase Pricing](https://firebase.google.com/pricing): **Spark — без оплаты и без способа платежа**. Обычный **Hosting**: 10 GB хранения сайта и 360 MB трафика в день. Firebase Authentication с почтой и паролем доступен бесплатно. Cloud Firestore Standard: 1 GiB данных, 50 000 чтений, 20 000 записей и 20 000 удалений документов в день.
- [Firebase pricing plans](https://firebase.google.com/docs/projects/billing/firebase-pricing-plans): Spark не требует платёжных данных. Превышение квоты ограничивает работу соответствующего сервиса, а не включает платную подписку. Период восстановления квоты зависит от продукта.

Используются только Hosting, Authentication и Firestore. Не нужны карта, Blaze, Cloud Billing, App Hosting, Cloud Functions, Cloud Storage, SMS, ИИ, аналитика или покупка домена. Публикация использует бесплатный адрес Firebase с HTTPS. Если консоль требует привязать карту или перейти на Blaze, остановитесь: выбран не тот продукт или тариф. Ничего оплачивать для этого проекта не требуется.

## 1. Создайте проект и личный вход

1. Откройте [Firebase Console](https://console.firebase.google.com/) под своим Google-аккаунтом → **Create a project / Создать проект**. Не включайте Google Analytics и Gemini. Оставьте тариф **Spark**. Не подключайте платёжный аккаунт.
2. В разделе **Build → Authentication → Get started → Sign-in method** включите только **Email/Password**. Затем **Users → Add user**: укажите свою почту и длинный уникальный пароль. Это вход в дневник, он может отличаться от пароля Google. Скопируйте **UID** созданного пользователя.
3. Откройте **Build → Firestore Database → Create database**. Выберите **Standard**, базу `(default)`, регион по вашему выбору и **Production mode**. Не выбирайте Test mode. База пока закрыта для всех; правильные правила будут опубликованы вместе с сайтом.
4. На главной странице проекта нажмите **Web / значок `</>`** → зарегистрируйте веб-приложение. Откройте **Project settings → General → Your apps → SDK setup and configuration → Config**. Оставьте открытым объект `firebaseConfig`. В нём нет пароля или серверного ключа.

## 2. Подключите дневник

Откройте PowerShell в этой папке. Node.js уже установлен на этом компьютере. Выполните:

```powershell
cd "C:\Users\imash\Desktop\my health\lichny-dnevnik"
npm.cmd install
npm.cmd run setup
```

Скрипт попросит:

1. Вставить объект `firebaseConfig` целиком. После него отдельной строкой напишите `КОНЕЦ` и нажмите Enter.
2. Вставить UID вашего пользователя из шага 1.
3. Подтвердить, что проект на Spark и без Billing, словом `SPARK`.

Он сохранит конфигурацию и ограничит серверные правила единственным UID владельца. Настройки Firebase в клиентском коде публичные; доступ обеспечивает проверка токена и UID в Firestore Rules. Другие аккаунты и анонимные посетители читать и изменять записи не могут.

## 3. Опубликуйте

```powershell
npx.cmd firebase login
npm.cmd run deploy
```

Первая команда откроет официальный Google-вход в браузере. Войдите в аккаунт, в котором создан проект. Вторая проверит настройки, попросит ещё раз проверить Spark, соберёт сайт и опубликует сайт и правила доступа. Она не меняет тариф и не создаёт платёжный аккаунт. **Не запускайте `firebase init`** — конфигурация уже подготовлена.

В конце Firebase напечатает **Hosting URL**. Это ваша готовая ссылка: откройте её на телефоне и войдите почтой и паролем из Authentication. Не публикуйте сайт до завершения настройки правил.

## 4. Быстрая проверка после публикации

1. С телефона войдите → в «Мыслях вслух» напишите короткую пробную запись → «Сохранить запись» → дождитесь «Сохранено».
2. Перезагрузите страницу: запись должна остаться. Измените текст и снова сохраните.
3. Откройте ссылку в другом браузере/на компьютере → войдите тем же аккаунтом → проверьте текст.
4. Отключите сеть после открытия дневника, измените запись и попробуйте сохранить. Должен появиться черновик, без «Сохранено». Включите сеть и нажмите «Повторить отправку».
5. Откройте историю, выберите дату, попробуйте отменить удаление, затем подтвердите удаление пробной записи.
6. Настройки → «Скачать все записи»: сохраните JSON в надёжном месте.

В мобильном браузере можно добавить ссылку на главный экран через меню браузера. Интерфейс после первого открытия доступен из офлайн-кэша; вход в первый раз, загрузка записей с сервера и отправка требуют интернета.

## Как хранятся данные

- Один документ на дату: `users/{UID}/entries/{YYYY-MM-DD}`. Любые поля можно оставить пустыми; для записи достаточно одного текстового поля или отметки.
- «Сохранено» появляется только после успешного ответа Firestore. Запросы к базе не кэшируются. Незавершённые отправки не считаются сохранёнными.
- При каждой правке черновик записывается в память этого браузера. Он привязан к проекту, UID и дате. Выход из аккаунта его не удаляет. Очистка данных браузера удалит его. На чужом устройстве после работы очистите черновики в настройках и выйдите.
- При ошибке сети можно повторить отправку. Повтор после потерянного ответа распознаётся по идентификатору операции. Если запись на другом устройстве изменилась, сайт сохраняет ваш черновик и предлагает скачать его и открыть серверную версию; автоматической перезаписи нет.
- Скачивание резервной копии читает **все** серверные страницы данных и добавляет черновики с текущего устройства. Импорт резервной копии в этой версии не предусмотрен.
- Проверка прав работает в базе, а не только в интерфейсе. Пароль проверяет Firebase Authentication. Google как поставщик инфраструктуры обрабатывает и хранит данные; это не сквозное шифрование от поставщика.
- Приложение не отправляет данные в ИИ, не ставит диагнозы и не даёт медицинских советов.

## Локальная разработка и проверки

```powershell
npm.cmd run dev
npm.cmd run build
npm.cmd test
```

Для `npm.cmd test` нужны Java 17+, Chrome и свободные порты 5173, 8080, 9099, 4400, 4500. На этом компьютере Java и Chrome обнаружены. Тесты используют отдельный проект **demo-tiho** в настоящих локальных эмуляторах Firebase, без обращения к вашей облачной базе и без оплаты. Они проверяют мобильный сценарий, второй браузер, историю, стресс 0 и пустые дни, редактирование, JSON-копию, подтверждение удаления, обрыв связи, ожидание сервера, конфликт устройств и запрет доступа постороннему. Результаты и снимки находятся в `test-results`.

Если Chrome находится в другом месте, задайте переменную `TEST_BROWSER` с путём к его исполняемому файлу. Для запуска с локальным Firebase на другом компьютере потребуется доступ к интернету для первого скачивания эмулятора.
